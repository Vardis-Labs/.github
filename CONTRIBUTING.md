# Contributing to Vartari Labs

Thank you for your interest in contributing.

Vartari Labs projects focus on local-first AI software, MCP integrations, privacy, and practical developer tooling.

## Before you start

- Check existing issues and pull requests before creating a new one.
- Use an issue to discuss larger changes before implementation.
- Keep pull requests focused on one clear problem.
- Never commit API keys, tokens, credentials, private datasets, or model files without an explicit project decision.

## Development workflow

1. Create a branch from `main`.
2. Use a descriptive branch name such as `feature/mcp-auth` or `fix/model-loading`.
3. Add or update tests where appropriate.
4. Run the project's formatting, linting, and test commands.
5. Open a pull request and describe what changed and why.

## Commit messages

Prefer short, imperative messages:

```text
Add MCP connector health check
Fix local model path resolution
Refactor Codex context builder
```

## Pull requests

A good pull request should include:

- a concise summary,
- motivation and context,
- testing steps,
- screenshots for user-interface changes,
- known limitations or follow-up work.

## Project principles

Contributions should support these principles:

- local-first operation,
- privacy by default,
- user-owned data,
- modular and understandable architecture,
- minimal unnecessary abstraction,
- secure handling of credentials and local services.

## Questions

Use the repository's issue tracker for project-specific questions and proposals.
